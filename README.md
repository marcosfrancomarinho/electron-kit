# Electron Kit

A minimal, type-safe toolkit for Electron applications.

The first version is built around one idea:

```text
Node -> providers.register() -> IPC/preload -> browser.get() -> Browser
```

The application code does not need to work directly with `ipcMain`, `ipcRenderer` or `contextBridge`.

## Core API

### Node

Create normal Node/Electron code:

```ts
// src/node/file.ts
import { readFile, writeFile } from 'node:fs/promises';

export const file = {
  read(path: string) {
    return readFile(path, 'utf8');
  },

  write(path: string, content: string) {
    return writeFile(path, content);
  }
};
```

Register what the Browser is allowed to use:

```ts
// src/providers.ts
import { providers } from 'electron-kit/node';
import { file } from './node/file.js';

export default providers
  .register('file', file)
  .register('version', () => '1.0.0');
```

Registration is chainable. A provider can be an object of functions or a function directly.

### Browser

```ts
import { browser } from 'electron-kit/browser';

const file = browser.get('file');

const content = await file.read('config.json');
const version = await browser.get('version')();
```

The provider names, parameters and return values are typed from the Node registration.

This is invalid:

```ts
browser.get('unknown');
file.read(123);
```

## Commands

```bash
electron-kit dev
electron-kit build
electron-kit package
electron-kit type
```

- `dev` builds the application, opens Electron and rebuilds/restarts when `src` changes.
- `build` builds the Node process, generated preload and Browser bundle.
- `package` builds and packages the desktop application with electron-builder.
- `type` generates the provider contract and checks the project with TypeScript.

A consuming project can expose them through npm:

```json
{
  "scripts": {
    "dev": "electron-kit dev",
    "build": "electron-kit build",
    "package": "electron-kit package",
    "type": "electron-kit type"
  }
}
```

## Project convention

The initial version uses a small convention instead of a large configuration file:

```text
src/
├── node/
│   ├── main.ts
│   └── file.ts
├── providers.ts
└── browser/
    ├── index.html
    └── main.ts
```

Generated files and compiled application files live under `.electron-kit/`.

For editor autocomplete, include the generated declarations in the application's `tsconfig.json`:

```json
{
  "include": [
    "src/**/*.ts",
    ".electron-kit/**/*.d.ts"
  ]
}
```

## Main process

`preloadPath()` points to the preload generated by Electron Kit:

```ts
import { app, BrowserWindow } from 'electron';
import { preloadPath } from 'electron-kit/node';
import './providers.js';

await app.whenReady();

const window = new BrowserWindow({
  webPreferences: {
    preload: preloadPath(),
    contextIsolation: true,
    nodeIntegration: false
  }
});

await window.loadFile('.electron-kit/dist/index.html');
```

## Type flow

Electron Kit does not require duplicate provider interfaces.

```text
providers.register('file', file)
            |
            v
   inferred TypeScript type
            |
            v
 generated provider contract
            |
            v
 browser.get('file')
            |
            v
 typed remote API
```

A synchronous Node provider becomes asynchronous in the Browser because the call crosses Electron IPC.

## Status

Early development. The public surface for the first version is intentionally small:

```ts
providers.register()
browser.get()
```

plus the four CLI commands: `dev`, `build`, `package` and `type`.
